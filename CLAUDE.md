# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Folio is a local-first book layout app for Linux (primary) and Windows 11, built with Tauri v2, React/TypeScript and Rust. It sits between Scribus and a friendly word processor: in **Easy** mode someone who has never heard of bleed can make a picture book and send it to Amazon KDP, and **Expert** mode exposes baseline grids, master pages, PDF/X and colour profiles. See `AGENTS.md` for the authoritative contributor conventions — most importantly: **Canadian English** spelling everywhere; **Conventional Commits** for commit messages but **never in PR titles**; the licence/copyright header on new source files; **no barrel files**; and **no pushes unless explicitly asked**. `spec/` describes product behaviour and architecture, and `docs/` holds the decision log.

## Status

**Early development.** The specification and the design prototype are complete; the application is being scaffolded from the shell outwards: workspace and tooling, the shared window chrome, native plugins, the Tauri shell, settings, dev automation, the main window and child windows, then the documentation site. The document model, spread canvas, ribbon, layout engine and exporters come after that. Scaffold only what the current milestone needs, not the whole tree speculatively.

`design/` holds the files of the original Claude Design prototype (`*.dc.html`, helper scripts, screenshots, icon studies). It is **reference only** — its code is not to be ported, adapted or structurally mirrored. Only the behaviour it demonstrates is authoritative, and only via `spec/`.

## Layout

Bun workspace monorepo + Cargo workspace (the app identifier, and so the data directory name, is `ca.liminalhq.folio`; see `AGENTS.md` → Repository Layout):

- `apps/folio` — the Tauri app: React frontend in `src/`, thin Rust composition root in `src-tauri/`
- `packages/chrome` — shared title bar, window menu, context menu, dialogs and settings shell (copied from Waypoint, tokens renamed to `--folio-*`, no domain imports)
- `packages/protocol` — TypeScript types generated by `ts-rs` from the Rust wire types (types only, never hand-edited)
- `crates/*` — pure Rust, no `tauri` dependency: `folio-model`, `folio-package`, `folio-presets`, `folio-protocol`, `folio-session`, `folio-settings`; planned `-layout`, `-export`, `-import`, `-color`, `-jax`
- `plugins/*` — Tauri plugins: the domains `folio-books` and `folio-settings`, and copies of the unpublished reusable `window-tearoff` and `window-effects`. Published plugins (`system-appearance`, `os-prefs`, `window-manager`) are registry dependencies, never copies
- `spec/` — the specification; `docs/` — decisions; `design/` — prototype reference; `site/` — the documentation site (Astro Starlight, deployed to GitHub Pages)

## Commands

```bash
bun install          # install workspace dependencies
bun run validate     # the local CI gate — must pass before opening/updating a PR (format, headers, case, browser storage, tsc, vitest, build, cargo fmt/clippy/nextest)
bun run format       # Prettier write
bun run format:check # Prettier check
bun run check:headers # licence-header check
bun run check:case   # no two modules whose names differ only by case (one file on Windows)
```

Also: `bun run tauri:dev` (MCP-drivable desktop shell — use this one for agent automation, not plain `tauri dev`; it merges `tauri.conf.dev.json` for `withGlobalTauri`), `bun run test:js`, `bun run test:rust`, `bun run build`. If host Rust tooling is unavailable, use the `ghcr.io/liminal-hq/tauri-dev-desktop:latest` container per `AGENTS.md` → Local Tooling.

## Architecture — the key things to understand

Read `spec/02-architecture.md` first; the rules that bite:

**Split by concern, compose in the app.** Each concern is its own crate or Tauri plugin; `src-tauri` only wires them together through traits from the pure crates. Plugins never call each other's Tauri APIs.

**Rust owns state; the frontend renders (D-02).** The document model lives in Rust. The UI sends intents and receives patches. One writer per piece of state, a monotonic revision, granular events after each mutation. Wire types are generated from Rust by `ts-rs` — never hand-edit generated files.

**Settings go through the settings plugin.** No `localStorage`, `sessionStorage` or IndexedDB for app state; `scripts/check-browser-storage.sh` fails the build if one appears.

**Windows are created in Rust, and shadowed.** `tauri.conf.json` keeps `"windows": []`; the `windows` module builds each window with `.shadow(true)` where the platform supports it (Windows draws it; Linux draws a CSS shadow inside a transparent margin).

**Tokens are Folio's own.** `--folio-*` and `data-folio-theme`, never `--wp-*`. Book paper is never themed.

**Reusable first, and published means dependency.** Generic plugins stay free of Folio concepts. If one is published on crates.io and npm, depend on it; copy only unpublished ones, with a `PROVENANCE.md`.

**One log stream.** `tauri-plugin-log` in `src-tauri` plus `src/services/logger.ts` (webview `console.*` redirected, tagged with the window label). Call `initLogger(label)` in every window entry.

**The Linux webview is WebKitGTK.** Verify performance, transparency and `backdrop-filter` work there, and on Wayland, not only in Chromium.

**Verify the numbers.** KDP and Kobo figures marked ⚠ in `spec/` must be checked against the live help pages before a release.

## Conventions (from AGENTS.md)

- **PR titles**: human-readable, imperative, sentence case, ~70 chars, **no Conventional Commit prefix**. Descriptions use `## Summary` + `## Test plan` (checklists, concrete commands). Every PR gets a category label (`enhancement`, `bug`, `documentation`, …) plus scope labels (`frontend`, `rust`, `plugin`, …). PRs open ready for review, not as drafts.
- **Commits**: Conventional Commits with markdown bodies (what/why, `test:` for test-only changes); backtick every code-level reference; write bodies to a file and `git commit -F` when they contain backticks.
- **Stacked work**: build large changes as a `gh stack`; `gh stack submit` pushes, so it needs an explicit go-ahead.
- **Licence headers** on new `.rs`/`.ts`/`.tsx`/`.js`/`.sh` source files (one-line summary + `(c) Copyright 2026 Liminal HQ, Scott Morris` + `SPDX-License-Identifier: Apache-2.0 OR MIT`); `scripts/check-headers.sh` enforces it.
- **Docs sync**: user-facing changes update `spec/`; design decisions add a `docs/decisions.md` entry; structural changes update `spec/02-architecture.md` in the same PR.
- **No hard wrapping**: write each markdown paragraph or list item as a single line and let viewers soft-wrap. Commit bodies are the exception.
- **Em dashes**: use a real `—`, never `--` as a substitute (not for CLI flags).
- **Authoring voice**: write comments, identifiers, docs and PR descriptions as the author of the artifact, for its future reader — no "this PR", reviewer names or commit SHAs. Commit messages are the exception.
- **CI/CD**: follows the house pipeline: quality gate in `ci.yml`, tag-driven `release.yml`, synchronised versions. Never push tags or dispatch workflows unless asked.
- **Git**: never push (especially force-push) unless explicitly asked; prefer the `gh` CLI for GitHub work.

Keep this file and `AGENTS.md` in sync: when a convention changes there, update the summary here in the same PR.
