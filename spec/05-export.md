# 05 · Export pipeline

One **Export book** dialog builds many targets in one pass. Each target has plain-language options (Easy) and full settings (Expert), and every target runs preflight first.

> **Verify every KDP and Kobo number below against the live help pages before release.** They change. Values here reflect our understanding as of Oct 2026 and are marked ⚠ where they need checking.

## Targets

| Target | Output | Notes |
|---|---|---|
| **Kindle** | `<slug>-kindle.epub` | KDP accepts EPUB uploads and converts them to Kindle formats. Reflowable for flowing books. Fixed-layout picture books are produced as fixed-layout EPUB 3, and the user is pointed to Kindle Kids' Book Creator / Kindle Create if KDP rejects direct fixed-layout upload ⚠ |
| **Kobo** | `<slug>.epub` + `<slug>.kepub.epub` | EPUB 3 for Kobo Writing Life. KEPUB adds `koboSpan` wrappers for faster page turns and better stats |
| **KDP paperback** | `<slug>-paperback-interior.pdf` + `<slug>-paperback-cover.pdf` | A plain print-ready PDF, not PDF/X (KDP's help pages never ask for it). Every font embedded (as a subset of the glyphs the book uses: D-72; ⚠ verify against KDP's help pages that a subset is accepted), transparent pictures flattened onto the page by Folio (D-81; ⚠ this row has long asked for flattened transparency, but KDP's help pages have not been checked to confirm KDP needs it, so Folio does it because this spec asks and it is harmless, and does not claim KDP requires it), no crop marks, bookmarks, comments, annotations or metadata beyond title and author, bleed on every page when any element bleeds (page width = trim + 0.125 in, height = trim + 0.25 in), single pages, 300 ppi images. The cover is one PDF in untagged DeviceCMYK with no spot colours ⚠. The interior is not tagged either: its file carries nothing beyond the title and author (D-82) |
| **KDP hardcover** | `<slug>-hardcover-interior.pdf` + `<slug>-hardcover-cover.pdf` | Case laminate; wrap-around cover with hinge ⚠ |
| **Print-shop PDF** | `<slug>-print-pdfx4.pdf` | PDF/X-4 (default) or X-1a, crop marks + bleed + slug optional, chosen output intent |
| **Sharing PDF** | `<slug>-share.pdf` | RGB, pictures prepared for a screen at 150 ppi (D-71), the front cover first, the pages, the back cover last (each at trim size, D-80), bookmarks from chapters (or spreads when there are none), spreads or single pages, tagged for screen readers (D-82) |

**Links (D-67).** Words that link (`Run.href`, spec 09) come out as links wherever the file can carry one. The reflowable EPUB writes `<a href>` round the words, and a link to a spread points at an `id` written where that spread begins in the story, in the chapter file that holds it (a link to the cover lands at the start of the story, and a link to a spread the book does not have goes to the first chapter, so no link in the file is broken). The fixed-layout EPUB writes the same `<a>` round the words of a line, and a link to a spread names the page file the spread begins on. The **Sharing PDF** carries a `/Link` annotation (no border) over the line box of each stretch of a link, with `/URI` for an address and a `/Dest` of the first page of the spread for a link to one; a link to a spread that is not in the file (outside the page range chosen, say) is left out, a link to a spread goes to the sheet that holds its first page when a sheet carries two pages, and the annotation follows a turned frame. Links are a choice in Expert mode (*Links* under *Navigation and information*): on for the Sharing PDF by default, and always off for the print-shop and KDP files. The **KDP paperback**, **hardcover** and **print-shop** files and the cover carry no link annotations, as the paperback row above has always said ⚠ verify against KDP's help pages before a release whether a link in an uploaded interior is accepted or flagged; Folio leaves them out because a printed link does nothing. The link colour and rule are drawn by the on-page view only: no exporter draws them, so how a link looks in a file is the style's and the run's own (underline it if it should show). Reader previews do not follow links.

Files land in `~/Books/<Title>/exports/` by default (Documents\Books on Windows). The Export dialog's **Put the files in** shows the folder in use, with **Choose a folder…** (the system's folder picker) and **Use the usual folder**. A choice is kept in the book when **Export** is pressed (as a path relative to the book's own folder when it is inside it, so the book can move, and in full otherwise) and as the person's default with **Make these my defaults** (always in full); a book's choice beats the person's. A folder that is not on this computer, such as a book opened on another machine, falls back to the usual `exports` folder and the done screen says so, together with anything that was changed for the destination ("Changed for KDP: pictures kept at 300 ppi"). The done state lists them and offers **Show in folder**, which opens Waypoint if it's installed, otherwise the system file manager.

## EPUB 3 writer

- OCF zip (`mimetype` stored first), `content.opf` (EPUB 3.3), `nav.xhtml`, optional `toc.ncx` for older readers.
- One XHTML file per chapter (flowing), or per page (fixed layout).
- **Reflowable:** semantic HTML (`<section epub:type="chapter">`, `<h1>`, `<p>`, `<figure>`/`<figcaption>`), a small CSS with relative units, no fixed font sizes on body text, and `font-family` with publisher fonts embedded only when the licence allows. Images are max 1600 px on the long edge (Expert: 2560 or original), JPEG q85 / PNG.
- **Fixed layout:** `rendition:layout pre-paginated`, `rendition:spread landscape|auto`, per-page `viewport` meta, a first document that is the cover picture (`cover.xhtml`, the front cover alone, set as a reflowable page inside the fixed-layout book so a reader scales it to the screen) so a reader that makes a thumbnail from the first document, and one that looks for the cover through `<meta name="cover">`, the `<guide>` or the nav's landmarks, finds it, absolutely positioned frames, text kept as live text where possible (so it stays accessible): each line is one positioned box holding its words as running text, with real spaces and no word placed on its own (a reader that sets a word wider than the book was laid out, or rounds each letter to whole pixels, moves the rest of the line along and does not run words into each other), a word laid out in pieces for hyphenation is one piece of text again, a justified line is set ragged, and each font is declared at the weight and style it is, with its file kind, so an e-reader that refuses a range of weights still uses the embedded font. Spreads that cross the gutter are split into a left page and a right page, with the image sliced at the gutter. The export writes the book twice: `<slug>-fixed.epub` for Kindle (KDP), Apple Books and other readers, and `<slug>-fixed.fxl.kepub.epub` to copy to a Kobo. A Kobo chooses its renderer for a sideloaded file by its name, and the `.fxl.kepub.epub` one is its fixed-layout renderer, which sets the pages as laid out (the plain `.epub` renderer crops and overlaps a fixed page's text). Checked on a Kobo Aura; not yet checked on a Kindle.
- Accessibility metadata: `schema:accessMode`, `accessibilityFeature`, `accessibilitySummary`. Alt text comes from each image frame's description (preflight asks for missing ones, gently).
- Cover image: 1600 × 2560 px JPEG (KDP's recommended ratio 1.6:1 ⚠), generated from the front cover.
- **Fixed layout for Kindle:** Amazon's converter refuses a fixed-layout EPUB without `<meta name="original-resolution" content="WxH"/>` (Kindle Previewer error E34002), so the package carries the page size there.
- **Checked with Amazon's own converter:** KDP converts an uploaded EPUB with the engine in Kindle Previewer, so `scripts/kindle-previewer.sh check BOOK.epub` (see `docs/kindle-previewer.md`) runs a book through Previewer's command line and fails on any error. Every EPUB Folio makes for Kindle converts there.
- **What goes where (built):** after an export the dialog offers *Where do these go?*, which says under each file what it is for and where to put it: the Kindle EPUB and the cover picture on KDP, the plain `.epub` on Kobo Writing Life, the `.kepub.epub` and `.fxl.kepub.epub` copied onto a Kobo, the paperback PDFs on KDP. It is shown on request, not by default.
- Validated with **EPUBCheck** in CI. The export job can optionally run a bundled EPUBCheck (Java not required if we ship the GraalVM native build; otherwise skipped with a note).

## KEPUB

KEPUB is EPUB plus `<span class="koboSpan" id="kobo.N.M">` around sentences, plus a `kobo.js`-free stylesheet. The file extension is `.kepub.epub`. It's generated from the same XHTML in a post-pass.

**Built so far:** the Export tab's **Export book** opens a dialog with the Sharing PDF and the KDP paperback interior (the others are still to come); it says how many things are waiting on you with a way to check the book first, makes the chosen files in the book's `exports` folder (beside its file, or in its folder under `Books` before it is saved), lists them with their sizes and **Show in folder**. **Quick PDF** makes the Sharing PDF at once. File names follow `<slug>-share.pdf` and `<slug>-paperback-interior.pdf`. Pictures, fonts kept in the book and the page scene (D-29) are what it draws; bleed, crop marks, PDF/X and the cover are still to come.

## PDF writer

- `krilla` (on `pdf-writer` and `subsetter`) for font subsetting, with the full glyph set for PDF/X and for the KDP targets; a spike confirms it can write PDF/X boxes and output intents, and `pdf-writer` is the fallback.
- **PDF/X-4** (default for print-shop): allows live transparency, but Folio flattens the pictures of this file by default (D-81); ICC-based output intent (GRACoL 2013 / FOGRA39 / user ICC), RGB images converted at export with `lcms2` (perceptual, behind a trait in `folio-colour`) or kept with an output intent (Expert choice).
- **Flatten transparent pictures (built, D-81):** a picture with see-through parts, such as a PNG with feathered edges, is blended onto what is behind it at export time, so the file holds no transparent picture (no soft mask) and the result is written like any other picture (photographic content as JPEG, flat art lossless). It is on, and locked on, for the KDP paperback interior and cover and the print-shop PDF/X-4 ("Print files are flattened, so nothing in them is see-through."); the Sharing PDF keeps transparency live unless Expert *Flatten transparent pictures* is ticked, which is smaller and exact. Folio only blends when it knows exactly what is behind the picture: the page's flat background colour (the page's own over the spread's across both pages over the master's; a swatch as the colour it shows as) or, where there is none, the bare paper, which a PDF shows as white. Another picture, a shape with a fill or outline, a table or words drawn before it (judged by their turned bounds, so a turned frame counts by its corners), a gradient, texture or picture background, or, in a file in ink, a colour with its own ink, are not guessed at: the picture stays see-through there and the export says so ("A see-through picture sits on other pictures or shapes, so it was left see-through (pages 4, 7)"). Words and art drawn after the picture sit on top and change nothing. The blend is in the gamma space of the pixels, source over, as a viewer blends a soft mask, after a picture is reduced with its colours weighted by their opacity (so edges keep their colour) and after any profile conversion, and in a file in ink before the separation. The same picture on pages of different colours is one picture for each colour. The size estimate runs the same code, so it matches the file. The front and back cover pages of a Sharing PDF (D-80) are judged like any other page, against their own background colour.
- **Print colour (built):** when a paperback file is ticked the Export dialog offers *Make the paperback interior in ink (CMYK)* and an optional path to the press's CMYK ICC profile. Ink is separated through that profile, or by a plain separation without one, and text stays black ink alone; the output is untagged DeviceCMYK as KDP wants, pictures included: each is separated pixel by pixel through the same profile (or plainly), written as lossless CMYK (a picture with transparency is flattened first, in sRGB, and then separated, so no RGB reaches the file; one that stays see-through, as *Flatten transparent pictures* describes, keeps a soft mask; a CMYK JPEG encoder is held back by its IJG licence, which `deny.toml` does not allow, so ink pictures are large for now), while a CMYK JPEG that is already small enough passes through unchanged. The paperback cover is always in ink. The print-shop PDF/X-4 is sRGB with an sRGB output intent, unless it is asked for in ink *and* given a press profile: then its colours and pictures are separated through that profile and its output intent is that CMYK profile (its name taken from the profile); ink without a profile leaves it sRGB. No press profile ships with Folio.
- **Pictures (built):** each picture is prepared for the file (D-71). Its size is worked out from the largest place it is drawn, a background included; it is reduced to the target's pixels per inch only when it has more than one and a half times as many (the Sharing PDF aims at 150 ppi, the paperback, cover and print-shop files at 300 ppi, and only a picture above 450 ppi is reduced); photographs are written as JPEG (Sharing quality 80, press files quality 90), flat art and pictures the person asked to keep lossless as pixels, and pictures with transparency as pixels with a soft mask (or, in a flattened file, blended onto the page first and then written like any other picture: see below), and a picture with no colour in grey. A JPEG within the limit passes through unchanged, keeping its own profile; a picture in another RGB profile is converted to sRGB when it is rewritten. The same picture on several pages is one object in the file. The book's picture is never changed, so a later export can choose differently. Picture presets (Small, Standard, High, Original) and finer controls follow in the Export dialog.
- **Ways round a PDF (exporter built; the Export dialog's controls follow):** the Sharing and print-shop PDFs can carry bookmarks (one for each chapter, spread or page, or *automatic*; chapters come from the engine's layout of each `h1` heading), page labels in the book's own numbering (roman front matter, arabic story, named sections without a number), the file's subject and keywords (the book's description and keywords unless changed) and a two-page viewer layout. A paperback interior or cover has none of these, only the title and author, whatever is asked; Bookmarks and labels survive the PDF/X-4 step. **Automatic bookmarks (D-80, the Sharing default):** *Front cover*, then one bookmark for each chapter when the book has chapter headings, or else one for each spread named by the numbers on its pages (*Pages 2–3*, or *Page 1* for a lone page, the app's own labels; an unnumbered spread takes its section's name, or its place in the interior when it has none, since a spread has no role such as title page to name it by), then *Back cover*. The words (`Front cover`, `Back cover`, `Page {n}`, `Pages {from}–{to}`) are passed in by the window so the exporter stays free of the app's language. A KDP file has no bookmarks whatever is asked. The file's Subject and Keywords are the book's description and keywords (Book details) unless the person writes others, for the Sharing and print-shop PDFs and never for KDP; a book with neither writes neither.
- **Tagged PDF (D-82, built):** a tagged file carries a structure tree, the book's language and the title in the viewer's title bar, so a screen reader can read it in order and describe its pictures. It is a choice in Expert mode (*Make the PDF readable by screen readers* under *Navigation and information*): on for the Sharing PDF, off for the print-shop PDF (which can be tagged), and always off, with the reason beside it, for the KDP interior and cover ("Changed for KDP: not tagged for screen readers"). The structure comes from `folio-export::structure::plan` and is drawn by the PDF writer with krilla: every mark of a page is a span of a paragraph, heading, note or table cell, a figure or an artifact, the front and back cover pages are read first and last, a barcode drawn on the back page is an artifact, a flattened picture is a figure like any other, and each link annotation is inside its link element with a description ("Link to https://…", "Go to page 4"). The text carries its spaces (the font's space glyph, written after each word and at the end of a line the paragraph goes on from, so a reader gets words and not letters), a hyphen the line ends on is a soft hyphen in the text, and a stretch in another language is marked with it. The tags change no pixel: a test renders a fixture with text, a picture, a link and both covers tagged and untagged at 100 ppi and compares them. The viewer is asked to show the title (`DisplayDocTitle`, written by `post.rs`, and by the PDF/X step for the print-shop file, which keeps the structure tree. Content is read in **reading order**: sheets in the file's order, pages left to right, and on a page rows from the top (frames whose heights overlap by more than half the shorter are one row), left to right inside a row, a story as one thread in the order of its frames, and the lines of one paragraph one element across frames and pages. Titles (`display`, `title`, `h1big`, `h1`) are headings, `numeral` and `h2` second-level headings, `epigraph` a block quote, `callout` and `footnote` notes, a `caption` after a picture a caption, tables a head and a body of cells, and words that link a link across the lines they run over. A picture with a description is a figure with that text as its alternative text; one without says only "figure", which is why the Export window warns of it. **Artifacts**, which a screen reader skips: backgrounds, everything that comes from a master, page numbers, running heads, the `spine` and `ornament` styles, table tints and rules, a shape's art unless it has a description, a picture frame still waiting for its picture, anything the person marked decorative or the decoration rule finds (see *Alt-text helper*: a number alone in the page-number position and the small undescribed picture behind it), and the copy of a frame that crosses the gutter on the page that does not hold its middle. An empty description never means decorative. Not covered: lists (read as paragraphs), captions are not linked to their pictures, colour contrast, right-to-left text, and a reading order that is a heuristic. A claim to PDF/UA is not made yet.
- **The program that made the file (D-74, built):** a Sharing PDF and a print-shop PDF say in their information that Folio made them: `Creator` is `Folio`, `Producer` is `Folio <version> (krilla)` and `CreationDate` is the time of the export, and the same go in the XMP (the PDF/X-4 step rewrites the XMP and the information and keeps them, along with `GTS_PDFXVersion` and the output intent). The KDP interior and cover carry none of it, because the paperback row above promises no metadata beyond the title and author. ⚠ That exception follows that rule and is to be revisited when KDP's help pages are checked: if KDP does not mind a producer, the paperback can say so too. The caller passes the version in (the engine reads the app's), so `folio-export` knows nothing of the app. The Expert panel *Navigation and information* says *Made with Folio* for the files that carry it.
- **Which pages and how they sit (exporter built):** the Sharing PDF reads like a book by default (D-80): the front cover first, the interior pages, the back cover last, each a page of the trim size with no spine. The back cover is the back panel of the cover spread (`x` from 0 to the trim width) cut out the way the front is: the cover's background fills the page, frames are clipped to the panel and a frame across the spine shows on both. It carries the generated ISBN barcode on white in the barcode box when the book has a good paperback ISBN and a barcode choice of Automatic or Make my own (Let KDP add it draws nothing). The cover choice is *Front cover only*, *Front and back cover* (the default), *Whole cover sheet (one wide page)* (back, spine and front side by side as one first page, Expert only) or *No cover*; a book saved with an older choice keeps it. The **page range counts the interior's physical pages from 1 and the covers come outside it**: a range of 2 to 4 with the front and back cover is five pages. A cover page has no number in the page labels and is named by its own name there (*Front cover*, *Back cover*, passed in by the window in the person's language), and each is a bookmark (first and last) in every bookmark list. With a spread to a sheet the two covers stay alone. A link to a spread goes to the sheet that holds its first page, and a link on the back cover is on the back page. The estimate makes exactly the same pages. Every other target is fixed at the whole book as single pages, with no back cover added (KDP's cover file has its own sheet).
- **Print-shop extras (exporter built):** crop marks are a choice (on by default for a print shop), the bleed is the book's own or a custom number of points (0 to 36), the room round the bleed that holds the marks is 18 to 72 points (24 by default), and the file can be in ink through a press profile. A paperback file never has marks or a different bleed.
- **Export settings (D-73, built in Rust; the dialog's controls follow):** every PDF choice (picture preset, pixels an inch, JPEG quality, lossless/lossy/automatic, keep JPEGs, bookmarks, page labels, links, tagging, file information, viewer layout, page range, cover, spreads, crop marks, bleed, room for marks, ink and press profile) is optional in each of four layers, built-in, your defaults, the book's, this export's, and `resolve` combines them. What each target locks: Sharing locks nothing; the KDP paperback and cover are kept at High or Original pictures (at least 300 ppi, JPEG quality at least 80), the whole book as single pages, no bookmarks, labels, links, tagging or information beyond title and author, no crop marks and KDP's own bleed; the print shop keeps those picture limits and the whole-book pages but may have bookmarks, labels, crop marks and a custom bleed, and never links; both also keep transparent pictures flattened (D-81). A value that is not allowed is put right and the export's answer lists what changed. The built-in Sharing PDF has automatic bookmarks, page labels and the front and back cover.
- **Size estimate (built in Rust):** `estimate_export` makes the PDFs of a request in memory exactly as an export would (same choices, same pictures) and answers with their total bytes and the book's picture count, so the Export dialog can say "About 3.8 MB" before anything is written. Each open book keeps the pictures it has prepared (up to 256 MB), so the export that follows reuses them; asking for a new estimate while one works stops the older, which answers `cancelled`. EPUBs and the cover picture are not counted.
- **Picture quality in the Export dialog (built):** below the list of files, each kind of PDF that is chosen has one **Picture quality** choice with a line for each: Small (for email), Standard (sharp on a screen, a modest file), High (for printing, 300 pixels an inch) and Original (every picture as it was brought in); the paperback and the print shop offer only High and Original. Under it the dialog says *About 3.8 MB*, worked out (`estimate_export`) 400 ms after the last change. The dialog opens with the person's defaults under the book's own choices; **Export** keeps what was changed in the book (one undo step) and **Make these my defaults** keeps it in Preferences → Export.
- **More choices in Expert mode (built):** under the quality choice the Export dialog has a **More choices** section with four panels: *Pictures* (pixels an inch, JPEG quality, automatic, lossy or lossless, never touch a JPEG), *Navigation and information* (bookmarks, page numbers, links, readable by screen readers, how a viewer opens the file, subject, keywords), *Pages and layout* (one page or a spread to a sheet, the cover, first and last page) and *Print extras* (crop marks, bleed, room for marks, ink through a press profile). When several kinds of file are chosen, a row of buttons picks which one the panels are for. A control that the file's destination fixes stays in view, greyed, with the reason beside it (a paperback carries only the title and author, is the whole book as single pages and has no marks; print files have no links). *Crop to frame* is not offered yet.
- **Progress and stopping (built):** while the Export dialog works it says *Making file 2 of 5: Kindle (EPUB)* and offers **Stop**, which ends the export before its next file and keeps what was made. Progress is per file, sent as `folio-books://export-progress`; a single large PDF is not interruptible part-way.
- **CMYK swatches (D-40, being built):** a book keeps named swatches (`Styles.swatches`, saved in `styles.json`), each with the sRGB `display` colour the screen, EPUBs and RGB files use and, optionally, the exact `ink` (whole percents of cyan, magenta, yellow and black) a file made in ink prints. A colour field holds `#rrggbb` or `swatch:<id>`, so editing a swatch changes every use; `Swatches::resolve` is the one place a reference becomes a colour, and a reference to a swatch the book does not have shows mid-grey and never stops a book opening. The display of an ink swatch is the plain inverse `(1 - plate)(1 - k)` until a press profile is in play. The book schema is 2, so an older build refuses a newer book instead of reading `swatch:` as hex. **Built so far:** the model (types, parsing, resolving, schema, saving) and two intents: `SetSwatch` (adds or replaces a swatch by id; a swatch with ink gets its display colour worked out from the ink) and `RemoveSwatch` (every use keeps the colour the swatch showed as, in one undo step). Shape fills and outlines, backgrounds and the colour of selected words refuse a reference to a swatch the book does not have. What is drawn (the canvas, the shelf, the reader preview, layout, the EPUBs, the sharing and print-shop PDFs) shows each swatch as its display colour: the books plugin resolves references before laying out or exporting, and the UI before drawing. **Exact ink:** a paperback interior or cover made in ink writes a swatch that has ink as exactly those percents of the four plates (DeviceCMYK, no profile conversion), and a swatch without ink, like any hex colour, is separated from its display colour (black text stays black ink alone); the print-shop PDF/X-4 stays sRGB and prints swatches as their display colour. **Using them:** in Expert mode the sidebar has a **Swatches** tab to add a swatch from a name and four ink percents (a preview shows the plain-inverse screen colour), change it or remove it; the book's swatches are listed, with their ink, in the colour picker (D-76) for the Text colour, shape fill and outline, page background and tint. **Preflight:** Check book says **a swatch lays down too much ink** (a warning when its four plates add up to more than 300%, a figure to verify against KDP's pages, which give 240% for some papers) and **a colour refers to a swatch the book does not have** (an error; it is drawn as grey), each once for a spread. **Rich black on small text** is a warning (a swatch with at least 80% black and at least 20% of cyan, magenta and yellow together, on words under 12 points in a text frame; said once for each swatch on a frame, and the words of a flow are not checked yet). Flows (long text) are covered when the flow stack lands. There are no spot colours (KDP rejects them).
- **Soft proof (built):** Export tab → **Soft proof** asks for the press's CMYK ICC file and shows the spread being looked at twice over, as drawn and as that press would print it (the page is drawn by the exporter's rasteriser and each pixel sent through the profile with Little CMS, perceptual intent), with how much of each page is a colour the press cannot reproduce. Under the pages it lists the book's swatches, each as drawn beside as printed, and says which the press cannot reproduce (`proof_spread` returns the pages and these colours together). It is a dialog and not yet a toggle on the canvas, and it assumes an sRGB screen because WebKitGTK does not colour-manage.
- **PDF/X-1a:2001**: flattened transparency and CMYK-only. Offered for printers that ask for it. Future work (D-42): it needs a CMYK output profile that may be bundled, and is not part of the current plan.
- TrimBox, BleedBox and MediaBox are set correctly. Crop marks and slug are only drawn when asked for (KDP must have **no** marks).
- Interior: single pages (not spreads) for KDP, page 1 on a recto, blank versos inserted where a chapter must open on the right.
- Validated in CI by Folio's own structural checks (boxes, output intent, embedded fonts) and, for EPUB, EPUBCheck. veraPDF covers PDF/A and PDF/UA but not PDF/X, so PDF/X gets a manual preflight before each release.

## KDP cover maths

```
spine (in) = pages × paper_factor
  paper_factor: white 0.002252 · cream 0.0025 · groundwood 0.00235 · premium colour 0.002347 · standard colour 0.002252   ⚠
paperback full cover:
  width  = bleed + back(trim.w) + spine + front(trim.w) + bleed      bleed = 0.125 in
  height = bleed + trim.h + bleed
hardcover (case laminate):
  wrap  ≈ 0.591 in each edge (15 mm), hinge ≈ 0.394 in beside the spine   ⚠ — use KDP's template table by trim × page count
spine text allowed only when pages ≥ 80 (paperback; KDP's own pages say 79 or 80, Folio takes the stricter) ⚠; keep 0.0625 in clear either side of the spine fold
barcode area: 2 × 1.2 in, bottom-right of the back cover, 0.25 in from trim edges (KDP prints the ISBN barcode there)
minimum pages: 24 (paperback) ⚠, 75 (hardcover) ⚠
```

The cover builder draws a live diagram (back · spine · front, bleed/wrap dashed, barcode box) with dimensions, and the cover artwork slots snap to those panels.

## Preflight

Issues are **fix-oriented**, sorted Waiting on you → Worth a look → Fine, shown as `IssueRow`s with a 6 px dot (never solid red blocks):

| Code | Message | Fix |
|---|---|---|
| `IMG-PLACEHOLDER` | "4 pictures are still placeholders" | "Drop the final artwork onto each frame. Export will leave tinted boxes otherwise." |
| `IMG-LOW-PPI` | "The picture on page 4 is 180 ppi at this size" | "It'll print a little soft. Use a larger file, or make it smaller on the page." |
| `BLEED-SHORT` | "A picture stops at the edge on page 7" | "Stretch it to the pink dashed line so no white sliver shows after trimming." |
| `TEXT-SAFE` | "Words sit outside the margin on page 12" | "Move them inside the purple lines — they might get trimmed." |
| `OVERSET` | "Chapter 3 has words that don't fit" | "Add pages, or let Folio add them for you." |

**Built so far:** the Export tab's **Check book** button opens a dialog that lays out every spread and lists what it finds in three groups (Waiting on you, Worth a look, For your information), worst first, each with the way to fix it and **Show me**, which goes to the page and selects the frame. Empty picture frames and pictures with no description are said once with a count. It covers the checks the engine has (words that do not fit, words outside the margin, pictures short of the bleed, missing and soft pictures, a missing font, an empty picture frame, no description, a link that goes nowhere). The Expert panel that stays open and the checks that need the exporters (spine, page count, embedding) are still to come.

## Job model

`ExportJob { targets, shared: { layout, images }, progress }`. Kindle and Kobo share the EPUB build, and paperback and print-shop share the PDF layout. Progress events go to the dialog, which can be hidden ("Hide": keep working, done toast later). Cancelling is safe at any point because temporary files are cleaned up.
