It is deliberately **not** Spindle's sidebar shell. Pages live in a horizontal **shelf** at the bottom, the way a printed proof sits on a table, and properties live in a **floating inspector card** on the right.

## Theme

Folio's own tokens (`--folio-*`, derived from Waypoint's native-flex set; see D-09), following the system's light/dark and accent (02 · D-04). Afterglow tokens are only mapped for Liminal components that read them (Button, Checkbox, TextInput, Select, IssueRow, Badge). Light mode sets `data-theme="afterglow-light"` alongside `data-folio-theme="light"`. Book paper is always `#fbfaf6` with ink `#1c1b20`.

## Title bar and app menu (D-06)

- `WindowTitleBar` with the title **exactly centred**: "{book title} — {kind}". Control style follows the desktop: KDE Breeze (square-ish hover, tight) on KDE, Windows 11 (46 px wide, red close, snap layouts on maximise hover) on Windows, macOS traffic lights (round red, yellow and green discs, glyphs on hover) on a Mac, and GNOME (round, spaced) on every other Linux desktop, Cinnamon included.
- **App menu**: `AppMenuButton` in the start slot (Folio mark + "Folio" + chevron). This is the primary menu when the menu bar is hidden:
  - New book… `Ctrl+N` · Open… `Ctrl+O` · Open recent ▸
  - Import text… · Import layout… (Scribus, IDML, EPUB)
  - Save `Ctrl+S` · Save as… · Export book… `Ctrl+E`
  - ☐ Show menu bar · ☐ Use the ribbon · ☐ Expert mode · ☐ Jax · ☑ Smart punctuation as I type (also in the Edit menu)
  - Preferences… `Ctrl+,` · Keyboard shortcuts `Ctrl+?` · About Folio
  - Quit `Ctrl+Q`
- **Closing with changes.** Closing a book (Close, New and Open replace the one being shown) or the main window (the ✕, Alt+F4, Quit) asks first, for each open book with changes worth keeping: **Save**, **Don’t save** or **Cancel**. A book never saved asks only once it has been touched, since starting a book and closing it again costs nothing. Save on a book with no file opens Save as, and cancelling that cancels the close; Cancel anywhere keeps every book open.
- **Autosave (D-27).** While a book has changes, Folio keeps a recovery copy of it every 30 seconds beside the real file, never over it. Preferences → Saving turns this off and sets how often (15 seconds, 30 seconds, 1 minute or 5 minutes). A save, or closing the book on purpose, takes the copy away; only a crash or a power cut leaves one, and the start screen offers it back.
- **Menu bar** (`MenuBar` from folio-chrome) is **off by default**. Turn it on from the app menu, View → Interface, or Preferences. A lone Alt or F10 opens it temporarily even when it's hidden (Waypoint behaviour).

## Menus: in-page by default, native when enabled

Folio follows Waypoint's experimental native-menu design (`docs/architecture/native-menus.md` in Waypoint):

- All menus render through `HostedContextMenu`, which takes the same props as `ContextMenu`. With **Preferences → Experimental → Native context menus** on (Linux/Windows main windows), it rasterises each SVG glyph to RGBA at 16 logical px × DPR, converts the items, and calls `show_native_menu(items, at)`. Otherwise it renders the in-page `ContextMenu`.
- The in-page menu is the guaranteed fallback: on timeout (1.5 s), unconvertible items (>200, nesting >3), a rejected command, or a popup that closes within 40 ms (tauri#13608 on GTK3/Wayland).
- **Every item has an icon** (Waypoint's `expectEveryItemHasIcon` test). Checkbox items lose their icon in native mode. That's acceptable.
- Native-eligible: canvas frame menu, page/background menu, shelf thumbnail menu. Always in-page: title bar window menu, ribbon dropdowns, the export dialog.

### Canvas context menus

- **Frame:** Cut `Ctrl+X` · Copy `Ctrl+C` · Paste `Ctrl+V` · — · Duplicate `Ctrl+D` · Bring to front · Send to back · (picture) Stretch to bleed · (text) Edit text `Enter` · — · Delete `Del` (danger)
- **Page background:** Paste `Ctrl+V` (centred where it was opened) · — · Add text box here · Add picture here · Add note box · — · Add pages after · Duplicate spread · — · ☐ Show margins · ☐ Show grid · ☐ Snap to guides

### Classic toolbar (one 44 px row)

`[New][Open][Save] | [Undo][Redo] | [Text box][Picture][Note] | Style ▾ | [B][I][⟸][≡][⟹] | [Front][Back] | [Margins][Grid][Bleed][Snap] | [Print][Kindle][Kobo] | [−][Fit][+] | [Ribbon]  …  [Easy|Expert] [Export book]`

Icon-only with tooltips, except the most-used insert buttons. All glyphs are 16 px, 1.3–1.4 px stroke, round caps (Waypoint glyph rules).

**Built so far:** the ribbon and the classic toolbar draw from `RIBBON_LAYOUT` (`apps/folio/src/ribbon/`) with every tab, group and control of the table above, the contextual Picture, Shape and Table tabs (shown once a selection can call for them), the Easy/Expert switch and the File button's menu. Document controls act on the open spread and the selection — Text box, Picture, shapes, Bold, Italic, size, the Paragraph group (alignment, line spacing, space before and after, indent and outdent, first-line indent, each acting on the paragraphs under the caret or selection of the open editor, or on every paragraph of the selected frame; D-58), To front, To back, Lock, Add/Duplicate/Remove pages, the page helpers (Margins, Grid, Bleed, Frame edges), Snap, zoom, and the Picture tab's Replace, Fit and Stretch to bleed — and the Picture and Shape tabs appear when one picture or shape is selected. **Master pages** (Expert) opens the master of the page on show for editing: the stage shows that master as a page of its own under a banner ("Editing master page A", **Done**, or Esc), frames and guides are added, moved and deleted on it like on a spread, and every page that uses it shows the change. The master's pictures and shapes are drawn on every page that uses it, and its text, with `{page}` filled in, comes from the layout. A book with no master gets master A (and B, with page numbers outside) the first time **Master pages** is used, and the page menu offers **Edit master page A** on a page that has one (Expert). Entering from the inspector comes next (D-22). The Home tab's **Smart punctuation** toggle (Editing group, pressed while `editing.smartPunctuation` is on, which it is by default) and the checkable **Smart punctuation as I type** item of the Edit menu and the app menu set the same personal setting as Preferences → Editing, and work with no book open (D-57). The Layout tab's **Units** menu sets the ruler units, and its Type grid toggles show and hide the baseline grid and the columns; **Contents** opens Book tools → Structure; **Ask Jax** shows Jax's panel while Jax is on; **Toolbar layout** switches between the ribbon and the classic toolbar; the Insert tab's **Note box** and the Home tab's **Shape** menu add frames; and **Paragraph style** applies a book style to the selected text boxes. The Layout tab's **Align** group lines the selected free frames up on an edge or a middle — with each other when two or more are selected, with the page when one is — and **Distribute** (three or more) leaves equal gaps across or down; a turned frame is measured on the box it fills, and each is one undo step. The Pages tab's **Book size** and **Margins** open small dialogs that set the trimmed page's width and height, or the four margins, in the display units as one undo step (the session refuses a page with no size or margins that leave no room for text; frames keep their places), and **Cover** shows the cover spread. **Link text** (Expert) starts the same chaining as the inspector's button for the one selected text box that is not chained yet: the next text box clicked takes the words on. The **Tools** tab opens each Book tool in the Book tools window on that tool (Spelling there is the same switch as Home's; Find & replace is listed and unavailable until it is built). The Font list draws the typefaces under two headings: **In this book** (kept in the book, bundled with Folio or used by the book) and **Installed** (the other fonts on this computer); the choice at the top, “Style’s font”, takes the font from the style. **Copy, Cut and Paste** work on the selected frames: the Edit menu, the frame menu and the page menu run them, and so do the keys, which also keep the webview from copying nothing and complaining. A paste adds copies with new ids, nudged 12 pt off the originals (and 12 pt further with each paste of the same copy); the page menu's Paste centres them where the menu was opened. A copy is the writer's own — neither locked nor tied to a master nor another place in a story's chain, as for Duplicate — and Cut takes off only the frames that are free, leaving a locked or a master's frame where it is. The Home tab's Clipboard group starts the ribbon: a large **Paste** (always there, since the system clipboard cannot be read from here), **Paste special** below it with **Paste in place** (the frames land exactly where they were copied from) and **Copy** and **Cut** (on a selection; Cut needs a frame that is free). A **picture** on the system clipboard (a screenshot, or one copied from a browser) pastes as a picture frame the size of Add → Picture, holding the picture, which is stored in the book once however often it is pasted (`import_image_bytes`). **Paste special** also has **Paste text only** (`Ctrl+Shift+V`: the words of the clipboard, or of the frames copied, in a new text box) and, with one free text box, shape or picture frame selected, **Paste into frame** (the words become its words; a picture, or the picture of a copied picture frame, becomes its picture). Reading the system clipboard from a menu depends on what the webview allows; the keys always work. Pasting a frame as a picture is not built. **Group** and **Ungroup** (Layout tab, the frame menu, the inspector, `Ctrl+G` and `Ctrl+Shift+G`) wrap two or more free frames in a group and take it apart again; a selected group has no turn handle and its inspector offers Ungroup (spec 11). **Sidebar layout** (only the grouped card is built) and **Import layout** (no layout importer yet) stay unavailable. Controls whose command is not built yet (bullets, numbers, drop cap and letter spacing among them) are listed but unavailable ("Not available yet"); Undo, Redo, New, Open, Save, Export (when it exists), the menu bar and the ribbon/classic switch run today. The Home tab's **Find & replace** button, the Tools tab's **Find & replace**, Edit → **Find…** (Ctrl+F) and **Replace…** (Ctrl+H) open the find bar over the page (D-62). The toolbar follows `interface.toolbar`.

**The ribbon fits the window; it never scrolls.** When the active tab's groups are wider than the panel, they give way from the right, as an office ribbon's do: first each group of buttons in turn drops the words beside its buttons and shows them as icons only, then each group in turn folds into one button with its name and first glyph, which drops the whole group down under it (Escape or a press elsewhere puts it away), and only when every group is folded and still does not fit do the last groups go under a **More** button that drops them down together. Widening the window brings the groups back. A folded button, like every other ribbon button, leaves the focus (and so the words selected in the on-page editor) where it was. The collapsed variant fits its dropped-down panel the same way; the simplified variant is unchanged. The Home tab's Paragraph group has a **Vertical alignment** menu (Top, Middle, Bottom, the current one ticked) for the selected text boxes and shapes with words, and the Properties panel's text section a segmented control of the same name (D-70).

## Page shelf

**Built so far:** the stage draws the selected spread on its paper (pages, trim and bleed, margins, column and baseline grids, picture placeholders, shapes and every text line from `layout_spread`, in the bundled fonts), with zoom from the stage header and Ctrl+= / Ctrl+− / Ctrl+0. The shelf draws a thumbnail of each spread from the model and selects it. Selection, moving frames, the Marks menu, drag-to-reorder and the shelf menu come next.

- Thumbnails are drawn from the model (no raster cache needed for v1): pages as paper, pictures as tints, text as ruled lines.
- Click selects; drag reorders (HTML5 DnD → `MoveSpread` intent); right-click opens the shelf menu; **+ Add pages** sits at the end.
- Labels come from page numbering: "Cover", "Page 1" (recto opener), "Pages 2–3".
- Long books virtualise the list and keep it bounded with "+ N more" groups by chapter.

## Inspector (floating card, 292 px)

- Header: what's selected + a badge (Text / Picture · Placeholder / Master A / Fixed layout / Flowing).
- **Nothing selected:** This book (kind, size, pages, layout, bleed) · Page helpers (checkboxes) · _Margins, bleed and grid (in/mm)_.
- **Text:** Words (Easy textarea) · Style chips (from the kind's style set) · Smaller/Bigger + pt readout · alignment segmented · **Paragraph** (Space before, Space after, Indent, First line and Line spacing of the paragraphs the ribbon's paragraph controls act on; D-58) · flow note · _Position and size (X/Y/W/H)_.
- **Picture:** drop zone + Choose picture… · fit (Fill frame / Fit inside) · Stretch to the bleed line · _Position and size_.
- **Master item:** explanation + Edit master page A (Expert).

## Welcome

Greeting by time of day → "What are you making?" six kind cards (live mini spreads) → a card with three questions (Book size chips · **How do you like to work?** Easy/Expert · **Would you like Jax's help?** Walk me through it / Just tips / No thanks) → **Start {kind}**. On the right: Pick up where you left off (recents), Bring something in (import words, open a layout, open a .folio).

**Built so far:** the welcome screen with the six kind cards, the three questions and **Start {kind}**, the recents, and **Open a Folio book…**. When a crash or a power cut left unsaved work (D-27), **Unsaved work from last time** heads the right-hand side, listing each book (newest first) with when its copy was kept and **Restore** or **Discard**; Restore opens the book as it was, still unsaved, with its real file or untitled if it was never saved. Opening a file that has such work asks whether to restore it or open the file as saved, which gives the work up. Import words and open a layout are listed as not available yet. **Guide me:** the welcome screen's **Guide me…** button and **File → New book…** (`Ctrl+N`) open the New book wizard window (`wizard-new`, 880 × 640, fixed, a child of the main window). Its seven steps are listed on the left, each clickable once reached and ticked once visited: what are you making (the six kind cards), size and paper, title and you (title, subtitle, author and an ISBN-13 checked as it is typed), bring your words (sample pages or empty; importing is not available yet), how you like to work (Easy or Expert and Jax), the look (typeface and cover colour) and a review whose **Make my book** button asks the books plugin for the book (`NewBookSpec`, D-18), saves the way of working to settings and closes the window. **Skip the wizard** is always there, and a refusal such as a bad ISBN is shown on the page. The book is added beside any already open and shown. The size step also offers **My own size** (width and height in inches, kept to what KDP prints: 4 to 8.5 in wide and 6 to 11.69 in high ⚠ verify) and says how thick the spine of a book of the kind's usual length is on the chosen paper. The look step shows the book's cover as it will be, drawn by the same code that exports it and drawn again as the typeface or colour changes (`preview_new_book`).

## Status bar

`{kind} · {trim} · {pages} pages · {fixed|flowing}` … `● Snapping on` · `Saved · {file}.folio` · **Jax perch** (`●‿● jax 🦦`, the mini Jax). Clicking the perch expands Jax into the shelf (07).

## Opening a book from the file manager (D-52)

Double-clicking a `.folio` file starts Folio with the book's path, or, when Folio is already running, hands the path to the running Folio and brings its main window forward; there is only ever one Folio. The book opens exactly as File → Open opens it: a book already showing is closed first (asking about unsaved changes), unsaved work a crash left on that file is offered for restoring, and a book already open is shown rather than opened twice. Several paths open one after another. Paths with spaces and non-ASCII characters are fine, and on Linux the desktop's `file://` addresses are read. A book that is missing, unreadable or not a Folio book is reported in a message naming the file and the reason, whatever is on screen.

## Updates (D-50)

Folio looks for a newer version only when asked. **Help → Check for updates…** opens the Update dialog and looks at once. **Preferences → Updates** (and a checkbox in the dialog) turn on a check when Folio starts, at most once a day; it is off to begin with, and the chip below offers it once.

A small chip sits at the right of the toolbar (the ribbon's end, before the Easy and Expert switch, and the classic toolbar's end) and says nothing while there is nothing to do. It says **Updates…** once, to someone not yet asked; **Update {version}** when a newer version is found; **Downloading {n}%** while it is fetched; and **Restart to update** when it is ready. Pressing it opens the dialog, which shows the release notes as plain text and how the install will go: a `.deb` or `.rpm` asks for the computer's password, Windows closes Folio while the installer runs, an AppImage replaces its own file. Installing first asks about every book with changes, as closing the window does. A copy that cannot update itself (a development build) says why and offers nothing.

## Accessibility

Every toolbar button has an accessible name and a tooltip. The canvas exposes frames as a listbox with roving focus (Tab cycles frames on the spread, Enter edits). Text is never only colour: guides also carry a legend in the Helpers section. Minimum target is 28 px (Waypoint row/control height), and 44 px in large-target mode (Preferences → Interface → Larger controls).

## Page marks (stage header → Marks)

**Built so far:** the stage header's Marks menu switches the bleed line, margins, column grid, baseline grid and frame edges on and off and picks each one's colour from four curated ones; the Page helpers in the inspector, the page menu and the Layout tab's helpers change the same settings. They are kept in the settings (`marks`), so they hold for every book and every run, along with whether dragging snaps. Smart guides, cover folds and the barcode area come with the covers.

Every on-page mark can be switched on or off and recoloured: bleed line, bleed area (hatched, trimmed off), safe margins, column grid, baseline grid, frame edges, smart guides, cover folds and spine, barcode area. Each mark has four curated colours. Marks never print or export. On/off states and colours are saved in preferences, and the same toggles appear in the Properties panel's Page helpers and on the Layout tab.

## Tooltips

Every toolbar, rail, mini toolbar and panel control has a tooltip after a 450 ms hover (60 ms when moving between controls). Each one shows the name, a keyboard shortcut chip where there is one, and a one-line description. They render in-app (not as native `title` tips) so they match the theme. Accessible names stay on the elements.
